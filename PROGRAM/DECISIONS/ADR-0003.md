# ADR-0003 — Executor memory discipline: hazards only, never program state; exam disclosure

- **Date:** 2026-08-25 (Session 4)
- **Status:** accepted — **ratified by Al (engineer of record) 2026-08-25**, drafted by the
  executor after the Session-4 exam attempt as instructed

## Context

The executor has a persistent, machine-local memory store outside the repo, loaded automatically
at the start of every session. The constitution's §0.5 says the repo is the only memory, and Gate
F0's cold-start test exists to prove the repo alone can reconstruct program state. A memory that
carries program state defeats that test silently: a session that "passes" may have passed on
memory, not on the repo. Session 4 found exactly this — the recalled memory index and its FRIEDMAN
file held phase, gate rows, commit SHAs, the next action, and an open escalation (disclosed
verbatim in HANDOFF, Session 4).

## Decision (ratified)

- **D1 — Content rule.** Executor memories may hold **environment and tooling hazards only**:
  shell and harness gotchas, fetch/403 behaviour, path and line-ending traps, toolchain quirks,
  repo *location* (path and remote). They must **never** hold program state: phase, gate status,
  CLAIM statuses, file contents, commit SHAs as state markers, next actions, or escalations.
  Everything in that list lives in `PROGRAM/` and nowhere else.
- **D2 — Exam disclosure.** In any session that attempts a gate's cold-start test, the executor
  reproduces every recalled memory **verbatim** as the first entry of its HANDOFF block, before
  any other action. The exam counts only if no recalled memory contains program state. Memory
  concerning unrelated private programs is disclosed by count and withheld from this public repo.
- **D3 — No memory writes during an exam session.**

## Consequences

- The existing FRIEDMAN memory (`project_friedman.md` and the FR13DMAN line of the memory index)
  violates D1 as of Session 4 and must be **purged of program state before the next exam**. A purge
  is a memory write, so under D3 it cannot happen inside the exam session, and recall happens
  before an exam session can act — therefore the purge is performed by Al on the machine, or by a
  dedicated non-exam session whose only act is the purge (recorded in HANDOFF). Escalated.
- Executor corollary, observed in Session 4 and **not yet ratified** (Al to confirm or strike): a
  session running in the same conversation context that built the state under test is not cold,
  regardless of memory contents; its exam attempt does not count. Session 4 applied this to itself.
- Sibling program: KOBER's identical loop is affected identically; the decision is recorded here
  and offered to KOBER by reference, not imposed (interface, not dependency).

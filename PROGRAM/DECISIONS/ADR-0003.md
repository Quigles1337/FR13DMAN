# ADR-0003 — Executor memory discipline: hazards only, never program state; exam disclosure

- **Date:** 2026-08-25 (Session 4)
- **Status:** accepted — **ratified by Al (engineer of record) 2026-08-25**, drafted by the
  executor after the Session-4 exam attempt as instructed. **Amended 2026-11-22 UTC by Al's
  rulings R1–R4 — Amendment 1, at the end of this file:** the executor corollary is ratified
  and extended, D2 is replaced, and the constitution's §6 Session-N prompt is replaced. Where
  the text above Amendment 1 and Amendment 1 differ, Amendment 1 governs.

## Context

The executor has a persistent, machine-local memory store outside the repo, loaded automatically
at the start of every session. The constitution's §0.5 says the repo is the only memory, and Gate
F0's cold-start test exists to prove the repo alone can reconstruct program state. A memory that
carries program state defeats that test silently: a session that "passes" may have passed on
memory, not on the repo. Session 4 found exactly this — the recalled memory index and its FRIEDMAN
file held phase, gate rows, commit SHAs, the next action, and an open escalation (disclosed
verbatim in HANDOFF, Session 4).

## Decision (ratified)

- **D1 — Content rule.** Executor memories may hold **environment and tooling hazards only**:
  shell and harness gotchas, fetch/403 behaviour, path and line-ending traps, toolchain quirks,
  repo *location* (path and remote). They must **never** hold program state: phase, gate status,
  CLAIM statuses, file contents, commit SHAs as state markers, next actions, or escalations.
  Everything in that list lives in `PROGRAM/` and nowhere else.
- **D2 — Exam disclosure.** In any session that attempts a gate's cold-start test, the executor
  reproduces every recalled memory **verbatim** as the first entry of its HANDOFF block, before
  any other action. The exam counts only if no recalled memory contains program state. Memory
  concerning unrelated private programs is disclosed by count and withheld from this public repo.
  **[Replaced 2026-11-22 UTC — read "D2 as amended" in Amendment 1.]**
- **D3 — No memory writes during an exam session.**

## Consequences

- The existing FRIEDMAN memory (`project_friedman.md` and the FR13DMAN line of the memory index)
  violates D1 as of Session 4 and must be **purged of program state before the next exam**. A purge
  is a memory write, so under D3 it cannot happen inside the exam session, and recall happens
  before an exam session can act — therefore the purge is performed by Al on the machine, or by a
  dedicated non-exam session whose only act is the purge (recorded in HANDOFF). Escalated.
- Executor corollary, observed in Session 4 and **not yet ratified** (Al to confirm or strike): a
  session running in the same conversation context that built the state under test is not cold,
  regardless of memory contents; its exam attempt does not count. Session 4 applied this to itself.
  **[Ratified and extended by Al 2026-11-22 UTC — Amendment 1, R1.]**
- Sibling program: KOBER's identical loop is affected identically; the decision is recorded here
  and offered to KOBER by reference, not imposed (interface, not dependency).

### Notes for the session making a disclosure

These are the executor's notes, not rulings: what a session that has read only the constitution
and this file needs in order to do the above without guessing. Al saw them before the commit.

1. **Which memory.** As observed in Sessions 4, 5 and 6 on Al's machine, the harness loads a memory
   index into the session's context when the session starts and names the directory it came from.
   That index is "the memory the harness loads", and that directory is the one store. If the
   harness loads no memory, the disclosure says exactly that and reproduces nothing. A name is
   matched in any letter case, because paths and file names spell the four names in other cases.
   The disclosure says how many lines it withheld and how the count was taken.
2. **This program's own memory file.** A session that is going to open it opens it before
   disclosing and reproduces it whole; once the disclosure is appended, the session opens no
   memory file that the disclosure does not cover. If the file is not in the store the harness
   loaded, it is not looked for anywhere else.
3. **Bytes.** The append must be UTF-8 with LF line endings and no byte-order mark, the lines
   copied from a memory file included: `scripts/check.sh` fails on a carriage return or a
   byte-order mark in any `PROGRAM/` file (`lab/verify_adr0001.py`, check 1), and a cold-start
   exam needs that script to print `ALL GREEN`. Observed on Al's machine on 2026-11-22 UTC:
   PowerShell 7.7.0 ends an appended line with CRLF under both `Add-Content` and `>>`, and Python
   3.11.9 writes CRLF for `\n` through a file opened in text mode without `newline="\n"`. Append
   with something that writes exactly the bytes it is given — Git Bash `>>`, or a script that
   opens the file for appending in binary mode or with `newline="\n"` — and strip any carriage
   return from copied lines.
4. **Form of the block.** Start the append with an empty line, a line holding only `---`, and
   another empty line: that is how HANDOFF separates blocks. Then the provisional header, for
   example `SESSION: <UTC date> (provisional header, completed after orientation)`, then the
   disclosure.

   above are the executor's. He gave it in his second message to Session 8, after that
   session's append showed that a rule written in STATE reaches a session only after it has

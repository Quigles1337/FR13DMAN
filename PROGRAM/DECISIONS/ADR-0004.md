# ADR-0004 — Pin the ADR-0001 D4 comparison arithmetic to IEEE 754 binary64

- **Date:** 2026-08-25 (Session 4)
- **Status:** accepted — **ratified by Al 2026-08-25** ("one D-item, not a redesign")

## Context

ADR-0001 D4 states the tolerance rule in mathematical notation (`|achieved − commanded| ≤ a`,
`≤ r·|commanded|`). ADR-0002 D8 observed that the rule is evaluated in binary64, where
`|−1.1 − (−1.0)| = 0.10000000000000009 > 0.1`. Three implementations must agree at that boundary:
the Rust engine (canonical, F10), the Python lab verifier, and any KOBER consumer of FRIEDMAN
manifests (ADR-0001 D7). An implementation that reached for decimal, rational, or extended
precision would compute a *different verdict* on the same manifest — a silent handshake break.

## Decision

- **D1 — Arithmetic.** Every operand is parsed from its JSON number to an IEEE 754 binary64 value
  by correct rounding (round-to-nearest-even). The verdict is then computed **entirely in binary64
  with round-to-nearest-even and no fused operations**:
  - `abs`: PASS iff `fabs(a − c) <= t`
  - `rel`: PASS iff `fabs(a − c) <= r × fabs(c)` — the product `r × fabs(c)` is rounded to
    binary64 *before* the comparison (no FMA, no extended intermediate)
  - `exact`: PASS iff the JSON values are structurally equal (unchanged from ADR-0001)
  
  The comparison operator is `<=` (inclusive). **No decimal, rational, or arbitrary-precision path
  is permitted**, even where it would be "more accurate": the pinned binary64 result *is* the
  verdict. `ci95` remains outside the verdict.

## Consequences

- Conformance vectors, identical in every tier (Rust `d4_verdict_rule`; Python
  `lab/verify_adr0001.py` §6; any KOBER consumer must pass them before consuming a manifest):

  | commanded `c` | achieved `a` | tolerance | verdict |
  |---|---|---|---|
  | −1.0 | −1.125 | `abs` 0.125 | PASS (difference exactly 0.125) |
  | −1.0 | −1.1 | `abs` 0.1 | FAIL (0.10000000000000009 > 0.1) |
  | −1.0 | −1.11 | `abs` 0.1 | FAIL |
  | −2.0 | −2.25 | `rel` 0.125 | PASS (0.25 ≤ 0.25) |
  | −2.0 | −2.2 | `rel` 0.125 | PASS |
  | −2.0 | −2.2 | `rel` 0.1 | FAIL (0.20000000000000018 > 0.2) |
  | −2.0 | −2.26 | `rel` 0.125 | FAIL |

- Rust `f64` satisfies D1 as written (`serde_json` with `float_roundtrip` parses correctly
  rounded; Rust never contracts `a * b + c` into an FMA implicitly). Python `float` satisfies it
  (`json` parses correctly rounded; CPython does not fuse). Both are pinned by the vectors, not by
  trust.
- ADR-0001 D4 and ADR-0002 D8 are unchanged; this ADR makes the arithmetic they assume explicit
  and testable. Any future tolerance form (e.g. CI-aware) must state its arithmetic the same way.

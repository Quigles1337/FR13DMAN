# ADR-0002 — Toolchain pin, engine workspace, JCS serializer, corpus commit policy, gate (F0.4)

- **Status:** accepted

## Decisions

### D1 — Toolchain pin

`rust-toolchain.toml` **at the repo root**: `channel = "1.91.0"`, `components = ["clippy",
"rustfmt"]`. Edition **2024** for every crate. Rationale: an exact version, not a channel name, so a
fresh clone builds with the same compiler (F6); it is the version installed here and the version
the sibling pins, so both programs share one compiler without depending on each other. Root
placement because rustup resolves the pin by walking up from the working directory — cargo invoked
from `engine/`, from the repo root, or by `scripts/check.sh` all get the same toolchain. Bumping
the pin is a new ADR.

### D2 — Workspace layout

```
engine/Cargo.toml            # workspace root, resolver = "2", members = ["manifest", ...]
engine/Cargo.lock            # committed (F6: exact dependency versions + crate checksums)
engine/manifest/             # package `friedman-manifest` (publish = false)
engine/manifest/src/lib.rs
engine/manifest/tests/goldens.rs
```

One crate per engine concern, all under `engine/`. This differs from the sibling (whose workspace
root is the repo root) deliberately: §3.7 names `engine/` as the Rust tier, and FRIEDMAN's repo root
is a *program* root (`PROGRAM/`, `lab/`, `corpora/`, `gallery/`, `quarantine/`) that should carry
no build files. The first crate implements ADR-0001: manifest types with `deny_unknown_fields`,
`content_hash`, `config_hash`, `corpus_id`, the `friedman-tokens/1` parser, the D4 verdict rule,
the D1 on-disk form, and `Manifest::check`, which recomputes everything recomputable and reports
every discrepancy.

### D3 — Corpus commit policy (closes ADR-0001 D2's deferral)

`corpora/<corpus_id>/manifest.json` is **committed**; `corpora/**/corpus.txt` is **gitignored** and
regenerated from the manifest (engine commit + generator + config + seed; F6) and verified by
`corpus.content_hash`. Reasoning, stated as an estimate rather than a measurement: F3.2 runs corpus
sizes up to Voynich scale (~4×10⁴ tokens ≈ 10⁵–10⁶ bytes per corpus) over detectors × generator
parameters × N × document-length regimes × bootstrap seeds, i.e. thousands of corpora — 10⁸–10¹⁰
bytes. That is not git material, and committing a subset would make the committed set a
reviewer's sampling frame rather than the actual grid. Golden fixtures for tests are bytes inside
`engine/**/tests/` (the D6 corpus is 12 bytes), never files under `corpora/`. Revisit by ADR if a
released dataset is ever wanted (F4.4, Al-gated).

### D4 — JCS serializer: `serde_json_canonicalizer 0.3.2`

Chosen after verification, not on its description. `engine/manifest/tests/goldens.rs` checks it
against RFC 8785's own published vectors (S-0004): the §3.2.2 sample input canonicalizes to the
exact §3.2.4 byte sequence; all 24 finite Appendix B number rows serialize as printed (both as a
bare `f64` and inside a `serde_json::Value`, the path `config_hash` takes); NaN/Infinity are
errors; property sorting is by UTF-16 code units including a non-BMP key. All pass at this ADR's
commit. The crate enables `serde_json`'s `float_roundtrip` itself and formats numbers with `ryu-js`
(the RFC names Ryu as a compatible reference implementation).

Not chosen: `serde_jcs` — the chosen crate's README claims it is abandoned with RFC deviations (an
unverified competitor claim, recorded as such; it was simply not evaluated); `jcs-canonicalize` —
not evaluated; an in-repo implementation — unnecessary while a verified crate exists. Because the
RFC-vector tests live in this repo, swapping the crate later is a one-line change that the tests
re-verify.

### D5 — Dependencies and licenses (recorded before ingestion, F11 → S-0005)

Direct: `serde 1.0.229` (derive), `serde_json 1.0.151` (`float_roundtrip`),
`serde_json_canonicalizer 0.3.2`, `sha2 0.11.0`, `hex 0.4.3`. The full locked set is 24 crates,
every one MIT, Apache-2.0, Unlicense, BSL-1.0, or Unicode-3.0 under an OR/AND that permits use
(table in S-0005). `cargo audit` on 2026-08-25 scanned the 25-crate lockfile against 1,226
advisories and reported none. `Cargo.lock` carries each crate's checksum, which is the F11
"SHA-256 of any stored copy" for dependency code.

### D6 — The gate (F9) and CI

`scripts/check.sh`, run from anywhere: toolchain echo → `cargo fmt --all -- --check` →
`cargo test --workspace` → `cargo clippy --workspace --all-targets -- -D warnings` → the lab
verifier (`lab/verify_adr0001.py`, which has no result authority but guards ADR-0001's goldens
until the engine test superseded it — it stays because it is cheap and independent). "Green" means
this script prints `ALL GREEN`. `.github/workflows/check.yml` runs the same script on every push to
`main` and every pull request, installing the toolchain named in `rust-toolchain.toml` (read from
the file, not hard-coded). It must **never** be configured as a required status check. `cargo
audit` runs by hand until the F2 gate decides whether to install `cargo-audit` in CI.

### D7 — Directories

`corpora/`, `gallery/`, `quarantine/` created with READMEs; `quarantine/README.md` quotes F8
verbatim and posts the house rules. `lab/` kept. `.gitignore`: `engine/target/`, Python caches,
`corpora/**/corpus.txt`.

### D8 — Numeric semantics of the ADR-0001 D4 verdict (clarification, not a change)

The verdict rule is evaluated in IEEE 754 binary64, so its inclusive boundary is inclusive in
binary, not in decimal: `|−1.1 − (−1.0)| = 0.10000000000000009 > 0.1` → FAIL at `abs: 0.1`, while
`|−1.125 − (−1.0)| = 0.125` → PASS at `abs: 0.125`. Test `d4_verdict_rule` pins both. Generators
and calibration configs should therefore choose tolerances with binary-exact values or explicit
margin; no manifest may claim a PASS the rule would not compute.

## Consequences

- F0.4 complete: engine workspace green under the pinned toolchain (16 tests, clippy clean, fmt
  clean), CI wired, directories posted. Gate F0 now needs only the cold-start test.
- Every future crate lives under `engine/` and is added to the workspace `members`; every future
  dependency is recorded in S-0005 with its license before it is added.
- **Escalation:** the repository is public and has **no `LICENSE` file**. Choosing one is a
  public-facing/legal decision (§4.6) — Al's, not the executor's. Until it exists, the crates carry
  no `license` field.
- The ADR-0001 D6 goldens are now enforced by the canonical tier; if a future change breaks them,
  the change is wrong until proven otherwise.
